- 2026-10-06 · **Motion rebuilt: real springs, derived durations, and a sheet you can throw.** A re-envisioning pass over the design rebuild found the motion layer furthest below the brief — and it was right: the “spring” was a hand-pasted 21-stop `linear()` sample of a 0.6 s curve that every entrance was then given only 320 ms to run in, so **every entrance in the app was cut off about half-way and landed with a jolt**; `transitionOf()` returned `none` for *everything* under reduced motion, deleting the cross-fades it promised; and not one interaction was velocity-aware or interruptible. **New `apps/web/src/motion/spring.ts`** — a dependency-free, DOM-free analytic solver for Apple's two parameters (`response`, `damping ratio`, critically damped at 1, under-damped below), returning value **and** velocity at any instant, plus `settleTime()` (the duration is *derived*: within 0.1 % of travel and moving at under 1 % of it per second), `springCurve()` (the `linear()` curve generated from that same solution), `projectMomentum()` (Apple's exponential-decay projection, `d ≈ 0.998`), `rubberband()`, and `springFrames()` (keyframes for the browser's own clock, so no `requestAnimationFrame` loop of ours can strand an animation). Entrances now use the pair `enterEasing()` + `enterDuration()` — measured in the browser at **0.546 s with a generated curve** — and bounce is spent only where a gesture carried momentum in (`SPRING_MOMENTUM`, damping 0.8 / response 0.3, Apple's drawer values). **New `useSheetDrag`** gives the quick-log sheet the gesture Apple actually ships: 1:1 pointer tracking with the paper's transition switched off, a (position, time) history so the release hands its **velocity** to the tension, the resting place chosen by **momentum projection** rather than release point, progressive **rubber-banding** when dragged the wrong way, and a settle driven by generated spring keyframes — grabbing it again mid-flight resumes from the **presentation value**, so an interrupted sheet never jumps. Two constraints are load-bearing and both are now documented: capture must happen on **pointer-down** (deferring it lost the gesture the moment a fast move left the strip) and capture **retargets the click** away from whatever it is taken on, so the region is the **grabber strip alone** and the Back/Close buttons sit outside it — the first attempt captured the whole header and silently broke every button in it, which the Playwright flow that closes the sheet caught. The rebuild also closed the app's last hard dependency on a delivered frame: `useEntrance` waited on a `requestAnimationFrame` and nothing else, so in a window whose animation clock never ticks it left **every entrance at `opacity: 0` — an invisible page**, not merely a missed animation. The frame is now the preferred moment to start an entrance rather than the only one (a one-shot timer races it), which was verified by stubbing `requestAnimationFrame` out entirely: the hero still reaches `opacity: 1` and the drag still dismisses. **Reduced motion now means what the HIG says** — a gentler equivalent: entrances became a declarative `crossFadeIn` keyframe (plays from first paint, no frame dependency), the movement and the press scale are dropped, `transitionOf()` keeps the colour/opacity/elevation changes instead of deleting them, and MUI's own blanket `0.01ms !important` CssBaseline rule is relaxed for animations (a more specific selector, since MUI's is emitted later) while its transition half is deliberately left squashed so MUI's own drawer *travel* cannot come back. `motionDuration` (dead code, and a lie: it claimed 0 under reduced motion) removed. Verified: `pnpm check` (664 modules, 0 violations), 63 Vitest files / **398 tests** (the solver is the app's first unit-tested module — `vitest.config.ts` gained a `web` project for DOM-free app logic, including a check that the analytic velocity is the actual derivative of the value), **11 Playwright flows** against a fresh build, and a scripted real-browser pass driving the gesture with pointer events: spring-back on a short drag, dismissal on a long drag and on a flick, no inherited transform on reopen, and — under reduced motion — a drag that moves nothing while the entrance still cross-fades at 0.2 s.

Day-adjustment numbers are computed in code (over budget when kcal left < 0; protein short when 4 × protein left > half the kcal left); the LLM only writes the note. Food matching penalises qualifier words (chocolate, cookie, butter, juice…) and uses an FTS5 index (`foods_fts`, trigger-synced).

The AI sees only allowed exercises for the day's split; the engine sets loads and muscle scores. Repair drops bad picks and fits total sets into 12–28 (12–16 when readiness is low or on a fast day; a deload week's 60 % is applied once, by the session plan), recording each drop in `guard_notes`. Accepting an AI workout passes `proposal_id` to POST /api/templates or /api/sessions. The library list is fetched once and filtered in the browser.

Comparisons and flags are recomputed on read; the debrief is an `ai_events` note dated on the scan day. If no AI answers and the lean-loss guard fires, the engine proposes protein +10 g. Manual entry = PATCH with a new id.

A redraft withdraws the earlier draft's pending proposals and never overwrites a Claude review. The report prints on 2 Letter pages for a normal week (3 in an extreme one). Locally the `BROWSER` binding has no `quickAction`, so Save PDF returns 501 and Print is the path.
  - *Photos:* trend weight and nearest scan are stored at upload and recomputed on read; the Worker checks only the file header (rejects non-JPEG/WebP and files still carrying EXIF) and never decodes images; signed photo links last 30 minutes and are never cached by the service worker; a test fails if the photos module imports the llm or jobs modules.
  - *Export/restore:* SQLite builds each export page's JSON (the Worker never parses rows); D1 limits (32 SQL-function arguments, compound SELECT terms) shaped the queries. Restore is gated to a fresh instance (or explicit overwrite) and marked with a `cron_runs` row; the monthly backup writes one table per 5-minute tick to `reports/backup/YYYY-MM/`, tracked in `cron_runs`.
  - *Push:* reminders are dispatched from the 5-minute cron by Edmonton local time, each once per local period (claims in `cron_runs`), quiet outside 07:00–22:00; subscriptions that return 404/410 are dropped.
